# Установка

Поставить и запустить Marvin — это три команды. Ниже — подробно, включая голос, Docker и телефон.

## Что понадобится

| Что | Обязательно? | Зачем |
|---|---|---|
| **Python 3.11–3.13** (советую 3.12) | да | на нём работает ядро |
| **Node.js 18+** | нет | только чтобы пересобрать интерфейс (`build_web.bat`). Собранный сайт уже в архиве |
| **Ollama** | нет | локальная модель для режимов `local` / `hybrid`. Без неё работают режим `cloud` и ~40 бытовых команд офлайн |
| **ffmpeg** | нет | некоторые голосовые форматы; OGG/Opus идут через PyAV и без него |
| **Telegram-бот** | нет | чтобы писать ассистенту из Telegram |

Ассистент работает **на твоём компьютере**. Данные лежат в папке `data/` рядом с проектом и никуда не уходят, пока ты сам не включишь облако.

## Windows

1. Поставь [Python 3.12](https://www.python.org/downloads/release/python-3120/) и при установке отметь галочку **«Add python.exe to PATH»**.
2. Запусти **`install.bat`** (двойной клик). Он создаст `.venv`, поставит зависимости (2–5 минут, ~300 МБ) и создаст `config.yaml` из примера.
3. Запусти **`start.bat`**. Откроется браузер с мастером первого запуска — пройди его: имя → мозг под твоё железо → ключ облака (по желанию) → Telegram-бот.
4. Если что-то не встало — **`doctor.bat`** скажет, что именно и что делать.

По желанию, голос:

```
install_voice.bat     :: один раз — распознавание речи и озвучка
voice.bat             :: голосовой клиент ПК (отдельное окно)
```

Пересобрать интерфейс после правок в `web/src`:

```
build_web.bat
```

## Linux / macOS

```sh
./install.sh     # .venv, зависимости, config.yaml
./start.sh       # запуск, откроется браузер с мастером
./doctor.sh      # проверка окружения
```

На macOS есть ещё `.command`-файлы (двойной клик из Finder): `Install-Mac.command`, `install.command`, `start.command`, `voice.command`, `autostart.command`, `update.command`, `build_web.command`, `phone.command`.

## Docker

В репозитории есть `Dockerfile` и `docker-compose.yml` (с отдельным контейнером Ollama):

```sh
docker compose up -d
```

Честно о контейнере: он без GPU (локальная модель будет медленной) и без доступа к рабочему столу ПК — то есть голос, экранное время и управление компьютером в Docker не работают. Для них запускай нативно.

## Что именно делает `install`

Установку делает `setup.py` (только стандартная библиотека, работает до установки чего-либо):

1. создаёт виртуальное окружение `.venv`;
2. ставит зависимости из `requirements.txt`;
3. копирует `config.example.yaml` → `config.yaml`, если его ещё нет.

`.env` установщик не создаёт — он не обязателен. Порядок настроек такой: **переменная окружения → `.env` → `config.yaml`** (что первое задано, то и побеждает). Всё нужное можно задать в `config.yaml` или прямо на сайте в «Настройках». Пример `.env` — файл `.env.example`.

## Первый запуск: мастер

При первом запуске любая страница ведёт на **`http://localhost:8765/setup`** — мастер настройки. Он:

- определяет железо и предлагает модель под него (видеокарта / оперативка);
- проверяет Telegram (токен бота и твой chat_id);
- проверяет Ollama и облачный ключ;
- записывает всё в `config.yaml`.

Мастер сам ничего не скачивает без твоего «да»: загрузку модели Ollama он запускает только по кнопке.

Пока мастер не пройден, ассистент не пускает дальше — это защита от «запустил наружу с пустыми настройками».

## Обновление

1. Скачай новую версию (или `git pull` в папке проекта).
2. Запусти `start.bat` — он сам дотянет недостающие библиотеки.
3. Если менялся интерфейс (`web/src`) — `build_web.bat`. Если менялась база — бэкап делается автоматически, но на всякий случай загляни в «Настройки → бэкапы».

## Автозапуск с системой

- Windows: `autostart.bat` — кладёт ярлык в автозагрузку.
- macOS: `autostart.command`.
- Linux: положи `start.sh` в автозапуск сессии (systemd/autostart — по вкусу).

## Проверка и ремонт: `doctor`

`doctor.bat` (или `./doctor.sh`) проверяет Python, `.venv`, библиотеки, `config.yaml`, папку `data/`, собранный сайт, доступность Ollama, ffmpeg и интернет — и человеческим языком пишет, чего не хватает и что с этим делать. Скриншоты в FAQ не нужны: сначала запусти `doctor`.
