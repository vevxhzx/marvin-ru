## Диагноз: почему ощущается как чат-бот

1. **Нет «сейчас».** Марвин знает всё о прошлом (база) и ничего о настоящем: в промпте нет ни активного окна, ни того, что человек 3 часа в Premiere, ни того, что он только что сел. Каждое сообщение — с чистого листа.
2. **Инициатива только по базе.** Поводы — «задача висит», «клиент не платит». Ни одного повода из реальной жизни: закончился рендер, вернулся после перерыва, сел утром.
3. **Нет целей — есть список дел.** «Что мне сегодня делать?» отвечается задачами с дедлайном, а не тем, что двигает что-то важное.
4. **Три ленты вместо одной.** Действия (Memory), экран (ScreenSlot), разговор (ChatMessage) — «что происходило вчера с проектом» не собрать.
5. **Решение «сказать/помолчать» размазано.** Тихие часы в scheduler, лимит в proactive, «человек в чате» в llm, голос в persona.

## Что сделано в 0.10.0 (по приоритету ТЗ: присутствие → польза → надёжность → контекст → цели)

### A. `services/state.py` — единое «сейчас» (разделы 1, 2, 14)
Один модуль, одна функция `snapshot()`: presence (active/idle/away/offline, с чего и как давно), активная программа/сайт и категория, сколько подряд в текущем занятии, игра/тяжёлая программа, был ли разговор недавно, фокус дня (из целей), сколько инициатив уже потрачено. Источник данных — уже существующие пульс и `ScreenSlot`, ничего нового не собирается.
Lifecycle: `active → idle (5 мин) → away (30 мин) → active`, переходы порождают события (см. B). Состояние переживает перезапуск: последний снимок хранится в `Setting`, при старте читается и Марвин знает, что «был перезапуск после N минут отсутствия», а не «первый раз вижу этого человека».
`state.line()` — одна строка для промпта («Сейчас: за ПК 2 ч 40 мин, Premiere Pro (работа) последние 50 мин»). Идёт в `now_line()` агента → модель знает контекст без лишних токенов (~30).

### B. `services/events.py` — событийный слой (раздел 3)
`emit(kind, key, **data)` → таблица `Event`-подобная? Нет — используем `Memory` с `kind="event"` и уникальным `key` через `Setting` для дедупа (TTL). Новых таблиц — одна: `Timeline` не нужна, `Memory` уже лента. Дедуп: тот же `key` в окне `dedup_sec` — игнорируется. Подписчики — обычные функции в процессе (`on(kind, fn)`); падение подписчика не валит эмиттер.
Источники событий сейчас: presence-переходы (`user_idle`, `user_back`, `user_arrived` утром), `long_session` (3 ч без перерыва), `app_started`/`app_stopped` для тяжёлых программ (рендер в Media Encoder/Premiere: «export started/finished» определяется по появлению/исчезновению процесса `Adobe Media Encoder`/окна «Экспорт» — честно: это эвристика, так и назвал `heavy_job_*`), `task_done`, `deadline_soon`, `background_failed` (из scheduler), `goal_step_done`, `milestone_done`.

### C. `brain/attention.py` — централизованная модель поведения (разделы 4, 14)
Одна функция `decide(kind, importance, now) → now | later | silent | voice` с явными факторами: presence, игра/тяжёлая программа (interruption cost), тихие часы, бюджет дня, «человек сейчас пишет», важность события, срочность. Заменяет разрозненные проверки в scheduler/proactive (они теперь зовут `attention`). Отложенные («later») — очередь в `Setting`, отдаётся при следующем `user_back`.
Attention budget: считается один для всего (proactive + событийные реакции), был только для proactive.

### D. Цели (разделы 5, 6, 7)
Новые таблицы `Aim` (долгосрочная цель; не `Goal` — он занят конвертами и трогать его нельзя) и `Milestone`. Иерархия ТЗ (goal→areas→projects→milestones→subgoals→tasks→actions) для одного человека — избыточна; сделано три уровня, которых достаточно и которые реально заполнятся: **цель → веха → задача** (`Task.aim_id`, `Task.milestone_id`). «Проект» = веха с несколькими задачами или заказ (`Order`) — привязывается к вехе через `Milestone.order_id`. Уровни «area/subgoal/action» не вводятся: пустые уровни — главный способ убить систему целей.
Прогресс вехи = доля закрытых задач; прогресс цели = доля закрытых вех (+ вручную `progress` если вех нет). `complete_task` → событие `goal_step_done` → если веха закрылась — `milestone_done` → Марвин говорит, что продвинулось и что логично дальше (`aims.next_actions`).
Планирование: `aims.focus(today)` → 1–3 действия, которые двигают активную цель: приоритет — ближайший дедлайн вехи, потом блокеры (задача, на которую ссылаются другие — нет, слишком сложно; блокер = задача с `blocked_by` текстом), потом самая старая незакрытая задача активной вехи. «Что мне сегодня делать?» → `rules()` ловит и отвечает из `focus()`, а не из LLM. Утренний дайджест получает строку «фокус дня». Не больше 3 пунктов — «меньше задач, больше сделанных».

### E. Timeline (раздел 8)
`services/timeline.py`: сшивает `Memory` + `ScreenSlot` (сессии и смены занятия >15 мин) + `ChatMessage` (только факт разговора, не текст) + события в одну ленту за день. «Что я сегодня делал» / «что было вчера с <проект>» → правило → текст из ленты (фильтр по имени проекта/цели по словам). `/api/timeline?day=` + вкладка «лента» в «памяти».

### F. Agent loop (раздел 9)
Минимальные точечные правки, не переписывание: (1) `registry.call` повторяет один раз transient-ошибки (`database is locked`, timeout) с паузой 0.3 с — для всех рисков кроме money (деньги не повторяем: риск двойной записи); (2) шаг-лимит был 4 — оставлен, но добавлен счётчик «пустых» шагов (модель отвечает без инструмента и без текста) → выход с честным ответом; (3) долгие фоновые работы (уборка, синхрон, ночная память) регистрируются в `state.jobs` с прогрессом → видно в статусе и `background_failed` уходит событием; (4) незавершённое подтверждение (`pending:*`) при перезапуске не теряется — оно и так в `Setting`, но теперь при старте, если ему < 5 мин, Марвин напоминает «я ждал вашего «да» на …».
Отмена: «отмена»/«стоп» во время ожидания подтверждения — снимает pending (было: только таймаут 5 мин).

### G. Self-monitoring (раздел 10)
`services/health.py::diagnose()` — один отчёт с выводами и советом: база (размер, WAL, последний бэкап), Ollama (доступна/модель есть/малая модель), облако (ключ/последний успех), ПК-клиент (пульс/SSE-слушатель — типичный сбой «пульс есть, команды не доходят»), планировщик (задачи, которые не запускались дольше 2 периодов), очередь gcal, ошибки TG. Каждый пункт: ok/warn/fail + что делать по-русски. `/api/diagnose`, «проверь себя»/«диагностика» в чате, карточка в настройках → состояние. `self_check` раз в день использует его же и **шлёт в TG только fail** (раньше — никогда; по просьбе владельца не слать шум — fail это не шум).

### H. Решения (раздел 12)
Не новая таблица: `Note` с тегом `#решение` + структура в тексте. «Решили: … потому что …» / «запиши решение …» → правило → `add_note` с title «Решение: …», tags `решение`, привязка к цели/вехе по словам. «Почему мы …?» → поиск по заметкам-решениям (слова + эмбеддинги, если есть) → ответ цитатой с датой. Не изобретаем сущность там, где хватает заметки с типом.

### I. Presence UX (раздел 13)
`LiveDot`/`LivePopover`: показывает не «мозг онлайн», а **чем занят Марвин и что видит**: «вы за ПК 2 ч 40 · Premiere Pro» / «отошли 12 мин» / «фоновая: ночная память 40 %» / «жду «да» на …». Карточка «фокус дня» на «Сегодня» (цель → веха → 1–3 действия, кнопка «сделал»). Страница «цели» — нет: цели живут внутри «задачи» третьей вкладкой (не плодим разделы; принцип minimal). Прогресс-полоски без градиентов.

### J. Security (раздел 15)
- `power shutdown/reboot` теперь требует «да» (как destructive), `lock/sleep` — нет (обратимо).
- `/api/pc/ping`: `title` режется до 200, `app` до 80, `idle_sec` ≥ 0 — защита от мусора в базе.
- Prompt injection через заголовок окна: заголовок активного окна попадает в промпт (`state.line()`) — только **имя программы и категория**, не title, если это браузер с неизвестным сайтом. Заголовки не идут в промпт никогда.
- Аудит инструментов: `run_tool` для `delete_*`/`stop_*`/`power` из API (`/api/tool`) — проверено, что такой ручки нет; инструменты вызываются только агентом. ОК.

### K. Routines (раздел 11) — сознательно минимально
Обнаружение повторов: последовательности категорий по дням из `ScreenSlot` (утро: Telegram → браузер → Premiere) — считаем, если 5+ дней одинаково, один раз (mute-урок) предлагаем «сделать утренний режим: открыть X, Y». Реально автоматизировать может только «открыть программы» через ПК-клиент — это и предлагается, ничего больше не обещаем.

## Что не сделано и почему
- Семиуровневая иерархия целей — вредна для одного человека, три уровня.
- Переписывание agent.py в «план → выполнение → проверка» с планировщиком шагов — модель 4b на 1660 Super не тянет многошаговое планирование; текущий цикл «инструмент → проверка по базе → truth_gate» надёжнее. Улучшены retry/выход/переживание перезапуска.
- Детекция «export completed» по-честному невозможна без хуков Premiere; сделана эвристика по процессу Media Encoder/окну экспорта и названа так, как есть.
- Отдельная страница целей, канбан, диаграммы Ганта — нет.
