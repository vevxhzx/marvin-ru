# Как превратить проект в цельный продукт

Документ-ответ на вопрос владельца: «поставил, открыл, пользуешься — и всё». Ниже — что уже работает,
что мешает и что делать по шагам. Приоритет — польза для реального человека, а не для разработчика.

## Что мешает сейчас (честно)

1. **Установка — это команды.** `install.bat`, `start.bat`, `phone.bat`, `voice.bat`: нужно знать, что и в каком порядке запускать, и держать в голове десяток файлов.
2. **Первый запуск — пустой.** Человек попадает на пустые экраны и не понимает, что делать дальше.
3. **Приложение живёт как «сайт на порту».** Ярлыка в меню «Пуск» нет, окна нет, трея нет, значка нет.
4. **Нет автообновления.** Вышел релиз — пользователь узнаёт об этом, только если зайдёт на GitHub.
5. **Нет «всё работает?» — одной кнопки.** Проверки разбросаны: диагностика в настройках, логи в папке, состояние модели — в другом месте.
6. **Облачный бэкап не предлагается при первом запуске**, хотя это единственное, что реально спасает данные при поломке.

## План по шагам

### Шаг 1. Один установщик вместо десятка файлов (самое важное)
`УСТАНОВИТЬ.bat` / `Установить.command` — один файл, который:
- проверяет окружение и сам говорит, чего не хватает (Python, ffmpeg, место);
- задаёт **три вопроса** в человеческом языке: как к вам обращаться, нужен ли голос, сразу ли настроить облачный бэкап;
- ставит зависимости, создаёт настройки, запускает ядро и **сам открывает браузер**;
- в конце печатает одну строку: «Готово. Открой http://localhost:8765», а для телефона — адрес и QR;
- умеет `--check` (ничего не ставит, только проверяет) и `--repair` (чинит сломанное окружение).
Уже сделано для macOS половина: `--check`, понятные ошибки, проверка порта. Осталось то же самое для Windows и единый диалог.

### Шаг 2. Мастер первого запуска
Четыре экрана в интерфейсе вместо пустоты:
1. «Как вас зовут и как к вам обращаться» — дальше ассистент использует это сам;
2. «Что у вас за работа» (необязательно) — влияет на подсказки по режиму жизни и налогу;
3. «Голос: да/нет» — сразу проверяет микрофон и говорит, работает ли;
4. «Облачный бэкап: настроить сейчас?» — три поля и кнопка «проверить соединение».
После мастера — один экран «всё работает»: модель, голос, Telegram, облако, последний бэкап, свободное место. Зелёное/жёлтое/красное и одна кнопка «починить».

### Шаг 3. Приложение, а не вкладка браузера
Обёртка на pywebview уже есть (`jarvis_app.py`). Нужно:
- собрать `.exe` для Windows и `.app` для macOS с иконкой и пунктом меню «Пуск/Applications»;
- значок в трее: открыть панель, включить микрофон, показать уведомления, выход;
- автозапуск вместе с системой (на Windows это «Запуск», на mac — LaunchAgent, который уже починен);
- окно с «поверх всех» для быстрого голосового ввода одной фразой.

### Шаг 4. Обновление одной кнопкой
В настройках: «Проверить обновления» → показ changelog в человеческих терминах → «обновить и перезапустить».
Механизм уже есть: релиз на GitHub с ZIP и тегами. Осталось дёргать релиз и показывать разницу версий.

### Шаг 5. Честная эксплуатация
- Раз в неделю — «итоги недели» уже есть; сделать так, чтобы он приходил сам (утром в Telegram) и был коротким.
- Раз в месяц — «сводка по деньгам» с учётом текущего режима жизни.
- Напоминание о бэкапе, если последнего нет больше двух дней.

### Шаг 6. Документация для человека, а не для разработчика
`docs/install.md` и `docs/macos.md` — уже написаны по шагам. Осталось сделать одну страницу «Первый запуск за 5 минут» с картинками.

## Порядок и оценка

1. **Шаг 1 и 2** — самые важные: без них продукт не «открывается», а «настраивается». Несколько дней работы.
2. **Шаг 3** — превращает в приложение. Требует сборщика (Inno Setup / pyinstaller), это отдельная задача и отдельные зависимости для сборки.
3. **Шаг 4** — маленькая, высокая польза.
4. **Шаги 5–6** — по мере сил.

## Чего делать не стоит

- Не прятать настройки под «продвинутым» режимом: человек должен видеть, куда он попадёт.
- Не требовать регистрации, аккаунта и интернета для базовой работы — сейчас всё работает локально, это главное преимущество, не теряйте его.
- Не добавлять зависимости в основной список ради удобства установки: облегчённый mac-набор уже показал, что одна тяжёлая библиотека ломает установку у целого класса пользователей.
