# Аудит мозга: вызовы моделей, память, скорость (17.09.2026)

Повод: три подряд ответа по 40–70 с, «Новиков», кот в каждом сообщении, «510 доставка еды» → мимо базы, «запиши 510 доставка еды» → заметка.

## Как устроен путь одной фразы (по коду, `agent._handle`)

```
фраза
 ├─ служебные («облако сброс», «проверь характер», смена голоса, игра) — мгновенно
 ├─ ссылки — сохраняются сразу
 ├─ «облако, …» / «локально, …» — явный выбор
 ├─ черновики/подтверждения («да», «календарь», «задача») — pending из базы
 ├─ СПИСОК? (sorter.looks_like_batch)  → нейронка раскладывает по типам
 ├─ СПОРНАЯ? (_disputed: «сайт 15000»)  → судья (малая модель/облако) или вопрос
 ├─ ПРАВИЛА (rules): траты, события, задачи, заметки, отчёты  ⚡ без модели
 ├─ РАЗГОВОР? (not is_personal) → облако Groq  ☁️
 └─ ЛИЧНОЕ → локальная Ollama + инструменты  🧠
      (после ответа в фоне: память извлекает факты — облако; связи/уборка — по расписанию)
```

Идея правильная: **дешёвое раньше дорогого**. Проблемы были не в архитектуре, а в том, что дорогие ступени ловили то, что должно было решиться дёшево, и в размере промпта для локальной модели.

## Ожидаемая скорость после правок (1660 Super, qwen3.5:4b, окно 8192)

| Тип фразы | Было | Станет |
|---|---|---|
| Трата/событие/задача шаблоном | 0.1 с (если попал) / 40–50 с (если не попал) | 0.1 с, попадает чаще (см. п.1–3, 9) |
| Разговор («как дела», «как думаешь…») | до 70 с (сортировщик + Ollama) | 2–5 с через Groq |
| Личное без шаблона («кот сожрал провод») | 40–50 с (7.5k промпт, перезагрузка) | ~10–15 с: 4.3k промпт, из них 3k в KV-кэше Ollama с прошлого раза |
| Личное про деньги/долги | 50 с | ~20 с (все 40 инструментов, но без перезагрузки) |

Первый запрос после простоя всё равно медленнее: Ollama читает системный промпт + схемы целиком (кэш пуст). Дальше меняется только хвост (память + реплика), и prompt_eval падает до сотен токенов — это видно в логе по строке «промпт N ток.».

## Моё мнение по разделу

**Работает как часы, не трогать:**
- Ступенчатая маршрутизация «правило → облако → локальная». Она даёт 0.1 с на 70 % бытовых фраз и не отправляет личное в облако.
- Стрим ответов, кэш энциклопедических вопросов на сутки, `keep_alive 2h`, `think: false` для qwen3 — всё это правильно и работает.
- Судья с уроками («это заказ» → в следующий раз не спросит) — маленькая, но очень удачная вещь.
- Память: слои short/long/archive, эмбеддинги локально, извлечение в фоне, секреты режутся до отправки. Архитектурно верно.
- Проверка правды после инструментов (`_truth_gate`, страж дублей, «модель сказала записал — проверяем базу»). Это то, чего нет у большинства подобных проектов.

**Перемудрено:**
- **`agent.py` — 1850 строк регулярок.** Каждый новый кейс = ещё одна регулярка + ещё одно исключение из чужой регулярки (я сегодня добавил четыре). Это работает, но хрупко: `ACTION_VERB_RX` ловит «заказ» как «заказать», `EVENT_NOUN_RX` считает обед событием, `TASK_REPORT_RX` ловит «как дела». Честная альтернатива — **маленькая локальная модель-классификатор** (qwen2.5:1.5b, `small_model` уже есть в конфиге!) на первом шаге: «это трата / событие / задача / заметка / вопрос о данных / разговор / список», 60 токенов ответа, ~0.5 с на вашей карте. Регулярки остаются как быстрый путь для очевидного, а спорное решает она, а не 40 исключений. Это следующий большой шаг, если хотите — отдельный план.
- **Три разных `where()` (память, связи, сортировщик, судья)** с одинаковым кодом cloud/auto/local. Работают, но это четыре копии одной логики — при следующем касании свести в одну функцию в `llm.py`.
- **Gemini-ветка в `llm.py`** (~300 строк: свой клиент, свой автоподбор модели, свои ошибки) — вы на Groq, Gemini отвергнут. Это мёртвый груз; удалять сейчас не стал (могут пользоваться в других сборках), но в личной версии он не нужен.
- **Промпт-правила для инструментов** (блок «У тебя есть инструменты…» — 2200 символов) частично дублируют описания самих инструментов. Для 4b-модели это шум; половину можно убрать, когда схем стало меньше. Не резал без живой проверки на вашем ПК.

**Что надо подправить (не сделал, требует вашего решения):**
- **`num_ctx: 8192` — оставить.** Не ставьте 16384: на 6 ГБ карте с 4b-моделью KV-кэш на 16k вытесняет веса в оперативку — вы это видели как «промпт 7525 ток. за 35 с». Лучше меньше промпт, чем больше окно.
- **`brain.ollama.small_model: "qwen2.5:1.5b"`** — включите. Судья и проактивные фразы уйдут на неё, основная не будет прыгать между задачами.
- **Проверить на живой модели**, что qwen3.5:4b не потеряла в качестве от урезанных схем: если на «переведи 5000 на наличные» она не найдёт `transfer` — `MONEY_RX` надо расширить словом, которое вы сказали. Стенд `route_audit.py` покажет, какая группа подключилась.
- Три спорных фразы в стенде: «кот опять сожрал провод», «меня зовут Вова, я монтажёр», «у меня день рождения 12 марта». Первые две идут в облако (разговор), память их всё равно извлечёт в фоне — по-моему, это правильно, но помечено как «ожидалось local». Третья — шаблон ставит событие на 12.03.2027 в 10:00 — тут лучше бы `add_person`/факт памяти, но это отдельная тема «люди».
