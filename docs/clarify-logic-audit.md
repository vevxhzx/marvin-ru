# Аудит логики обработки запросов (чаттинг): уточнения, ответы, исправления

Скоуп: только человеческая логика вопросов/ответов. Код reminder/finance-цепочек уже чинен
(см. тесты `tests/test_remind_audit.py`, 20 шт.). Здесь — что осталось в области «живой речи».
Статусы: FACT (проверено чтением/тестом) / DECISION (нужно решение хозяина, не гадаем).

## Ранжированные находки

### 1. Один общий слот на все вопросы — concurrent-вопросы затирают друг друга [FACT]
`pending:{channel}` один (`agent.py:111-115`). Открыт «календарь или задача?» →
пользователь пишет «перевёл 5000» → pay_ask ПЕРЕЗАПИСЫВАЕТ слот → ответ «календарь»
уже ничему не соответствует (generic-резолвер чужие префиксы пропускает, `agent.py:1117`).
Фраза-пример: Q1 вопрос → Q2 вопрос → ответ на Q1 = тишина.
DECISION: очередь вопросов / замена с уведомлением («про календарь забыли — сначала про деньги») / единый реестр слотов.

### 2. pay_ask ест слот ДО проверки, остальные — после [FACT]
`rules/orders.py:69` consume-first: любое сообщение (даже чужое) снимает вопрос, дальше `return None`.
Generic-путь (`agent.py:1146-1148`) и judge (`rules/edit.py:174`) — наоборот, peek-first.
DECISION: унифицировать на peek-first Dirt cheap, но меняет задокументированное
« unrelated chatter clears the slot» — подтвердить.

### 3. Голые «да/нет» идут в resolver раньше специализированных [FACT]
`_resolve_pending` (generic) бежит в `_handle` ДО `rules()`. Открыт только transfer-слот,
пользователь говорит «нет» → generic видит... (transfer — отдельный ключ, generic его не трогает,
дальше transfer-резолвер отменяет — ОК). Но: открыт generic «календарь?» + transfer-«сколько?»,
пользователь говорит «нет» (имел в виду перевод) → generic съедает как «Понял, забыли»
(`agent.py:1164`), transfer-слот висит дальше. Предложение: побеждает НОВЕЙШИЙ вопрос
(сравнить TS слотов) — реализуемо, мелкое решение подтвердить.

### 4. Ответы с довеском не матчатся в якорные regex [FACT]
«календарь, и напомни за час» — `CLARIFY_RX` (`^...$`, `agent.py:95`) не матчится →
слот жив, фраза утекает дальше. «завтра в 10, и это очень важно» как ответ на «когда?» →
в title утекает «, и это очень важно» (`agent.py:1151-53`). Предложение: матчить префикс
ответа + резать хвостовые клаузы. Реализуемо без решений.

### 5. Исправления на лету: «в пятницу, нет, в субботу» [FACT, DECISION открыт]
Проверено: берётся ПЕРВАЯ дата (пятница), «нет, в субботу» гниёт в заголовке.
Варианты: last-wins / переспрос «пятница или суббота?» / оставить. Жду решения.

### 6. Внутридневное прошлое врёт подтверждением [FACT, DECISION открыт]
«напомни сегодня в 10» в 14:00 → мёртвое событие + «Напомню в 09:30». Голден 197
требует запись — менять только решением спеки. Далёкое прошлое уже режется
(`_past_reply`, только строго прошлые дни).

### 7. В промпте нет запрета выдумывать записи [FACT]
`system_prompt` (`persona.py:65-113`) + характер: ни слова про «действуй только
инструментами / не заявляй о записях и отменах, которых не делал». Класс галлюцинации
со скрина 2 (отмена несуществующей «траты на пиво») лечится двумя строками в промпт.
Дешево, нужен тест на присутствие фразы. Предлагаю сделать следующим шагом.

### 8. Мелочи (по возможности, без решений)
- `remind|` без what: title из второго сообщения (`agent.py:1142-43`).
- Repeat-путь чистит заголовок уже, чем общий (`agent.py:824` vs `_clean_event_title`).
- TTL-экспайри ведёт себя честно (чистка + фраза идёт как новая) — без действий.
