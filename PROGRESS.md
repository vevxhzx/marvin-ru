## ЧАСТЬ 1Б, п.1 — Стадия КЛИЕНТА (backend) — ВЫПОЛНЕНО (2026-10-01)

- **Вторая сущность рядом с воронкой заказов:** новый модуль `core/crm/client_stages.py` (чистая функция
  `auto_stage` + работа с БД). Стадии: `лид → переговоры → клиент → постоянный → спит/ушёл`.
  Воронка заказов (`core/crm/stages.py`, 9 стадий) не тронута.
- **Авто-правила (приоритет постоянный → клиент → спит):** ≥1 оплаченный заказ → `клиент`; ≥2 → `постоянный`;
  нет активности ≥90 дней → `спит`; иначе авто-сигнала нет и текущее значение **не перетирается**.
- **Ручное значение приоритетнее:** `client.stage_manual=True` (колонка), авто обновляет только `stage_auto`;
  снятие ручного режима = `DELETE /api/crm/clients/{cid}/stage/manual` («вернуть авто»). Авто-режим включается
  и сам после оплаты заказа (`service.payment`).
- **Миграция v3** (`core/migrations.py::_v3_client_stage`) — только аддитивно и идемпотентно: `client.stage`
  (+индекс), `stage_manual`, `stage_auto`, `stage_updated_at`, дефолты; без DROP/переименований, авто-бэкап не тронут.
  Новых таблиц нет. Версия схемы → 3 (обновлены ожидания в тестах фаз 2 и 4).
- **API (только новые пути `/api/crm/*`):** `GET /client-stages`, `GET/PUT /clients/{cid}/stage`,
  `DELETE /clients/{cid}/stage/manual`, `POST /clients/{cid}/stage/recalc`, `POST /client-stages/recalc`;
  дополнительно карточка клиента получила поле `stage`. Подробности и формат ответа — `reviews/A2_client_stage.md`.
- **Тесты:** `tests/test_review_client_stage.py` (+12) — правила, авто-переходы (клиент/постоянный/спит), приоритет
  manual и снятие manual, идемпотентность миграции v3 на временной копии БД (реальная `data/*.db` не открывается),
  обратная совместимость `stage=''`. Прогон: **460 passed, 2 warnings** (только baseline-предупреждения).
  Веб-часть (UI стадии клиента) — отдельной задачей фронтенд-субагента.

### Не сделано / отложено (осознанно, с причинами)

Остатки **не блокируют работу** — всё ниже это «можно докрутить», а не сломанные сценарии. Файлы и критерии готовности — в разделе для следующего агента.

- **CRM (Фаза 4, углубление):** нет кнопки «напомнить через N дней»/snooze у follow-up (есть create/complete/scan). Нет графика дохода по клиентам за месяцы (аналитика отдаёт цифры, показ — текст/топ). В карточке клиента «следующий шаг» без даты в UI (бэкенд `next_step_at` есть). «Ссылки на ТЗ/файлы» заказа показываются как `board_id`/notes, без превью ссылок.
- **Прогноз (Фаза 5):** пессимистичный сценарий использует единую константу задержки 14 дней, а не фактическую привычку оплат конкретного клиента (`pulse.client_pay_habits`). На графике — строка-сводка, без второго пунктирного ряда.
- **Безопасность (Фаза 6), отложено как рискованное:**
  - подтверждение на **каждый** скриншот в облако требует асинхронного согласования клиент↔ядро и меняет привычный UX «что на экране»; сейчас закрыто явным `brain.vision.where=cloud` + `allow_cloud` и запретом молчаливого fallback в `auto`;
  - **обезличивание изображений** технически невозможно (в облако идёт пиксель-контент) — есть только «не отправлять»;
  - в режиме `brain.mode=cloud` результаты инструментов могут уходить в облако — это явный выбор режима, менять логику в фазе 6 рискованно;
  - хвост API-ключа в логах (`llm.py`) маскирован, но остаётся в логах — не наша фаза.
- **Фаза 1, мелочь:** шаблоны `persona.py` с `{days} дн.` сознательно не переводили на `plural` (нужно менять сигнатуру вызовов); аббревиатура допустима — отдельной задачей при желании.
- **Фаза 3, мобильный вид:** живой скриншот не делался (для него нужен сервер на реальной БД, что запрещено правилами) — проверка по классам + ручной чек-лист владельца.
- **Фаза 7 пропущена** по решению владельца: `app.py` не разбивался на роутеры.

**A. Скриншот/файлы → облако.** Путь: голос «что на экране» → `core/pc/loop.py` снимает экран → `POST /api/vision/ask`

## Этап 4 — Telegram — ВЫПОЛНЕНО

- **Напоминания**: кнопки **✅ Сделано / ⏱ 15 мин / 🌆 Вечером / 📅 Завтра** (было «Иду / +1 час / Завтра»).
  «Вечером» — сегодня 19:00, если уже позже — завтра 19:00 (`_evening`). После нажатия сообщение редактируется,
  кнопки убираются, показывается итог.
