# Roadmap

Приоритеты: **P0** — сделать до того, как кто-то ещё поставит проект; **P1** — ближайший релиз; **P2** — когда будет время; **P3** — по желанию.

## P0 — проверить на реальном Windows (правки аудита написаны в Linux-песочнице)

- [ ] `start.bat` → сайт на ПК открывается без вопросов; `data/api_token` создан.
- [ ] Телефон: старая закладка без ключа → «Нет доступа…»; QR из ⚙ Настроек → «с телефона» → сайт работает, после перезагрузки телефона — тоже (cookie на год).
- [ ] `voice.bat` на том же ПК — работает без изменений (loopback).
- [ ] «Открой блокнот», «открой хром», «открой телеграм» — `open_app` через App Paths / меню «Пуск» находит программы (раньше это делал `start`).
- [ ] Docker: `docker compose up` → ссылка с ключом в логах → мастер открывается.

## P1 — ближайший релиз

- [ ] **Подтверждение действий из недоверенного контекста** (F3): если инструмент `add_expense`/`add_debt`/`transfer` вызван в ответ на текст, пришедший из заметки/ссылки/OCR чека, — спрашивать «да/нет» через уже существующий pending-механизм.
- [ ] `_ANSWER_CACHE`: не кэшировать ответы на вопросы со словами «сегодня/сейчас/завтра/какой день/который час»; TTL до полуночи (F9).
- [ ] Лимит размера загрузки `/api/notes/photo` и `/api/finance/import` — 25 МБ (F14).
- [ ] В логе не печатать хвост облачного ключа — только «задан» (F12).
- [ ] Тест на `misfire_grace_time`: планировщик с «просроченным» cron выполняет задачу один раз (F8).
- [ ] Восстановление из бэкапа одной кнопкой (сейчас — вручную скопировать `.db` и `media/`): ⚙ Настройки → «восстановить» с выбором даты.

## P2 — надёжность и качество

- [ ] Pending-подтверждения привязать к id вопроса, а не только к каналу (F10).
- [ ] Разбить `core/api/app.py` на роутеры (`finance`, `calendar`, `notes`, `settings`, `setup`) **при следующей крупной фиче**, не отдельным PR «ради структуры» (F11).
- [ ] `agent.py`: вынести постобработку ответов LLM (`_claims_saved`, `_forced_tool`, `_russian_only`) в `core/brain/guards.py` с собственными тестами.
- [ ] Rate-limit на `/api/chat` с не-loopback адресов (например 30/мин) — защита от залипшей кнопки/скрипта на телефоне, который дёргает LLM.
- [ ] Health-проверка Ollama с таймаутом в мастере: сейчас при зависшем Ollama мастер ждёт до таймаута httpx.
- [ ] Тесты Telegram-хендлеров через фейковый `Message` (owner / не-owner, голос, фото) (F15).
- [ ] `voice_client.py`: разбить на `audio.py` (микрофон/VAD) и `client.py` (HTTP/состояние) — 858 строк в одном файле с глобальными состояниями.

## P3 — гигиена и удобство

- [ ] `pyproject.toml` вместо `setup.py` + `requirements.txt`; закрепить версии (`aiogram`, `apscheduler<4` уже закреплён).
- [ ] CI: добавить `ruff` (только `E,F`, без стилистики) и `python -m compileall`.
- [ ] Экспорт/импорт всей базы в JSON для переезда между ПК/Docker (сейчас — копирование папки `data/`).
- [ ] Один общий `Reply`-объект с полем `source` для всех каналов, чтобы метка ⚡/🧠/☁️ ставилась в одном месте, а не в каждом канале.
- [ ] Документировать протокол SSE (`/api/events/stream`) — какие события и поля бывают — для тех, кто захочет писать своих клиентов.

## Не планируется (осознанно)

- Многопользовательский режим, роли, пароли/PIN на сайте — проект для одного человека; доступ ограничивается токеном + VPN (Tailscale).
- HTTPS внутри проекта — Tailscale шифрует канал; для VPS ставить reverse-proxy (Caddy) снаружи.
- Переписывание на другой стек / микросервисы / очереди — не нужно при текущей нагрузке (один пользователь, SQLite).
