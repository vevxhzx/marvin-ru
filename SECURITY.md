# Правила безопасности проекта Marvin

Документ выделен из `OVERNIGHT.md` (раздел «ЖЁСТКИЕ ПРАВИЛА БЕЗОПАСНОСТИ» и связанные пункты),
чтобы правила безопасности лежали в одном месте и не терялись среди плановых задач.

Действует для всех, кто правит проект: людей и агентов. Нарушение этих правил ломает
работоспособность проекта или может утечь личные данные и ключи.

---

## 1. Секреты и личные данные

- **Нельзя трогать и нельзя показывать:** `config.yaml`, `.env`, `data/` (в т.ч. `data/jarvis.db`),
  `vendor/`, любые ключи и токены (Telegram, Google OAuth, облачные LLM, WebDAV, ключ API).
- Ключи живут только в `config.yaml` и `.env`. В коде, логах, ответах API, отчётах и коммитах
  значения ключей **не появляются** — максимум «задан / не задан».
- `.gitignore` обязан закрывать `.env`, `config.yaml`, `data/`, `backups/`, `*.db*`.
  То же самое — `.dockerignore`, иначе секреты попадут в Docker-образ.
- Никогда не открывать `data/jarvis.db` и другие боевые базы на запись из проверок.
  Только `file:…?mode=ro` для чтения, тесты — на временных копиях.
- Не запускать сервер и не гонять миграции на реальной базе.
- Собранный бандл `web/site` не должен содержать реальных значений секретов.

## 2. Данные пользователя не теряем

- **Данные пользователя не удалять.** Миграции БД только аддитивные (новые таблицы и колонки
  со значениями по умолчанию), идемпотентные, без `DROP` и без переименований.
  Единственное исключение — v10: удаление пустой таблицы-сироты `schemaversion`
  (двойник `SchemaVersion` без явного `__tablename__`; только если `COUNT(*)=0`, иначе warning).
- Перед применением миграции автоматически делается бэкап файла БД в `backups/`.
- Существующие заказы, клиенты, финансы, заметки и настройки должны остаться как есть.
- Файлы проекта не удалять (кроме `git rm -r --cached __pycache__`).

## 3. Обратная совместимость

- Не переименовывать и не удалять существующие эндпоинты, поля API, команды `core/brain/quick.py`,
  ключи настроек. Только добавлять.
- Новая фича — за настройкой; по умолчанию поведение не меняется, тесты не ломаются.

## 4. Локальность и приватность (local-first)

- Режимы `local` / `hybrid` / `cloud`. В режиме `local` **в облако не уходит ничего**:
  ни текст, ни картинки, ни файлы.
- Скриншоты, фото и файлы не отправляются в облако без явного подтверждения.
- Команды управления ПК принимаются только из разрешённых каналов владельца
  (голос, его Telegram ID) и **не** из содержимого заметок, ссылок, фото и пересланных сообщений.
- Перед отправкой в облако персональные данные обезличиваются.

## 5. Доступ и защита API

- Ключ доступа к API сравнивается постоянным временем (`hmac.compare_digest` / `secrets.compare_digest`).
- Опасные и системные endpoints (`/api/backups*`, `/api/settings`, `/api/pc/*`, импорт/экспорт,
  восстановление) доступны только с самого компьютера владельца.
- Ограничение частоты запросов: и на чат, и на подбор ключа доступа.
- Никаких SQL через f-строки с пользовательским вводом, `shell=True`, `eval/exec/pickle`,
  `yaml.load` без SafeLoader.
- Любой вывод в HTML экранируется; `dangerouslySetInnerHTML`/`innerHTML` не применяются.
- Загрузки: лимит размера, проверка типа файла, безопасное имя (без выхода за пределы каталога).
- Ошибки наружу — короткий JSON без `traceback`, путей файлов и имён модулей.

## 6. Зависимости и окружение

- Новые зависимости не добавляются без необходимости; если без новой не обойтись —
  перечислить в `PROGRESS.md`.
- Пин версий не сужать без причины (ломает обновление у пользователя).
- Docker/CI: `permissions: contents: read`, без секретов в workflow и артефактах,
  `no-new-privileges`, секреты в образ не копируются.

## 7. Рабочий режим

- Один логический шаг = один коммит с понятным сообщением (латиницей) и явным списком путей.
- После каждой фазы — тесты (`pytest tests -q`), сборка сайта (`npm run build` в `web/`) и тег `checkpoint-N`.
- Новый падающий тест = задача не выполнена (починить или откатить и записать причину в `PROGRESS.md`).
- Перед правкой прочитать нужный кусок файла; правки точечные, без массового форматирования.
- Не трогать календарь (неодинаковая ширина колонок задумана) и правые отступы страниц.
- Не рефакторить `agent.py`/`app.py` «ради красоты».
- После каждой фазы обновлять `PROGRESS.md`: что сделано, что нет и почему, риски, чек-лист ручной проверки.

## Быстрая проверка перед коммитом и деплоем

```bat
:: 1. ключи не утёкли
git grep -n -I -E "(api[_-]?key|secret|token|password)\s*[:=]\s*[\"'][A-Za-z0-9_\-]{16,}"
git log --all --name-only -- config.yaml data .env backups

:: 2. код в порядке
python -m pytest tests -q
cd web && npm run build && cd ..

:: 3. в индексе нет секретов и данных
git ls-files | findstr /R "config.yaml ^data/ ^backups/ .env$"
```

## 8. Копии секретов в бэкапах

- `backups/config-<дата>/` содержат живые секреты: `config.yaml`, `data/api_token`,
  `data/session_secret` (`google_token.json` в копии не входит — долгоживущий OAuth
  refresh-токен, автовосстановления из копий нет).
- Копии информативные: `restore_backup` подменяет только БД; возврат ключей — вручную
  через скачивание файла бэкапа (`resolve_backup_file` / `GET /api/backups/.../download`).
- Скопированные файлы получают права `0o600` (best-effort, на Windows игнорируется).
- Ротация при утечке копии: кнопка «новый ключ» (`auth.rotate()` — новый `data/api_token`
  + сброс всех Telegram-сессий через `tg_auth.rotate_secret()`); ключи облака/Google
  менять вручную в их кабинетах.

## 9. Время жизни сессий

- Cookie `assistant_session`: `max_age=90*86400` (90 дней, `core/api/auth.py`).
- Telegram-сессия (`assistant_tg`): `TG_SESSION_DAYS=30` (`core/api/tg_auth.py`).
- Ротация только вручную: кнопка «новый ключ» (`auth.rotate()`).
