# Безопасность

Проект по умолчанию локальный: всё работает на твоём компьютере, и до тех пор, пока ты сам не включишь облако или публичный доступ, наружу ничего не уходит. Но ассистент умеет открывать сайты, ходить в сеть, выполнять действия на ПК и отдавать сайт по сети — значит, поверхности для атаки есть. Если нашёл дыру — расскажи, пожалуйста, тихо.

## Как сообщить

1. **Не создавай публичный issue** с деталями уязвимости.
2. Используй **private vulnerability reporting** на GitHub: вкладка **Security** → **Report a vulnerability**. Это приватный канал, видный только мейнтейнеру.
3. Если такой возможности нет — создай issue **без деталей** («есть вопрос по безопасности, нужен приватный канал») и дождись ответа.
4. Приложи по возможности: версию (`core/__init__.py`), ОС, режим (`local`/`hybrid`/`cloud`), шаги воспроизведения и минимальный PoC. Секреты из логов вырежи.

Я стараюсь ответить и закрыть подтверждённые дыры; публично поблагодарю, если не против.

## Что считается уязвимостью

- **Обход доступа к API**: запрос не с loopback без ключа; запрос через прокси с `X-Forwarded-*`, принятый за локальный; подделка или повтор `initData` Telegram Mini App; вход чужим `owner_id`; обход лимита попыток входа.
- **Утечка или подмена секретов**: токен бота, `data/api_token`, `data/session_secret` и ключи облака видны в ответах API, логах, карточках или бэкапах в незамаскированном виде.
- **Инъекции**: промпт-инъекция, после которой ассистент вызывает инструмент `destructive`/денежный без подтверждения или отправляет личное в облако; инъекция в заголовок окна / текст чужой страницы, ломающая правила «данные — не команды».
- **Работа с путями и файлами**: выход за пределы разрешённых папок в `/media`, ассетах досок, уборке, поиске файлов; запись или перезапись чужих файлов.
- **Сеть на стороне сервера (SSRF)**: превью ссылок или импорт, достучавшиеся до внутренних адресов; обход проверки хостов.
- **XSS/CSRF** в сайте: исполнение скрипта из данных (заметка, имя, заголовок ссылки) или смена настроек/выключение ПК с чужого origin.
- **Отказ в обслуживании**: неограниченный `/api/chat` с внешнего адреса, разрастание данных, падение процесса из-за одного запроса.

## Что уязвимостью не считается (осознанные решения)

- **Публичный адрес Funnel сам по себе.** Любой может открыть `https://…ts.net` и увидеть экран входа — данных там нет. Это про доступ, а не про утечку. Разбор — [docs/telegram-miniapp.md](docs/telegram-miniapp.md).
- **Отсутствие многопользовательского режима, ролей и паролей.** Проект для одного человека; доступ ограничивается ключом и Tailscale.
- **Отсутствие HTTPS внутри проекта.** Канал шифрует Tailscale или внешний reverse-proxy.
- **Режим `cloud`.** Он честно отправляет данные провайдеру — это выбор пользователя, а не дыра. Сравнение режимов — [docs/PRIVACY.md](docs/PRIVACY.md).

## Где хранятся секреты

| Секрет | Где лежит | В git |
|---|---|---|
| Токен Telegram-бота | `config.yaml` → `telegram.token`, либо `ASSISTANT_TG_TOKEN` | нет (`.gitignore`) |
| Ключи облака (Groq, OpenRouter, NVIDIA, DeepSeek, Gemini, custom) | `config.yaml` → `brain.cloud.api_key`, `brain.gemini.api_key`, либо переменные окружения | нет |
| Google OAuth client_secret | `config.yaml` → `google.client_secret` | нет |
| Ключ доступа к API с других устройств | `data/api_token` (создаётся сам, права 600 вне Windows) | нет (`data/` в `.gitignore`) |
| Секрет серверных сессий Telegram Mini App | `data/session_secret` | нет |
| Секреты в пользовательском тексте (пароли, ключи) | не хранятся: `is_personal` относит их к личному, `anonymize` вырезает перед облаком | — |

В API секреты из `config.yaml` отдаются **замаскированными**, и сохранение маски не затирает настоящий ключ. `.env` и `config.yaml` никогда не попадают в архив релиза (собирается из git).

## Что ты можешь сделать сам

- Не открывай публичный доступ (`funnel.bat`, брандмауэр), если он не нужен.
- Держи `config.yaml` под закрытым диском и не пересылай его.
- Кнопка **«новый ключ доступа»** отзывает старые ссылки **и все Telegram-сессии** — хороший первый шаг, если телефон потерялся.
- Для максимальной приватности — `brain.mode: local` (см. [docs/PRIVACY.md](docs/PRIVACY.md)).
- Обновляйся: старые версии могут содержать уже исправленные дыры.
