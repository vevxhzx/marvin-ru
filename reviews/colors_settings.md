# Отчёт · ЧАСТЬ 1В — Настройки: выбор цвета (компактные свотчи, аккордеон, контраст AA)

Ветка `overnight-crm`, коммит `settings: compact color swatches with palette accordion and AA contrast`, тег `checkpoint-colors`.

## Что было

- «тема и цвет»: главный акцент — ряд кругов `.sw` **38px** (13 произвольных hex, `ACCENT_SWATCHES`), подписи нет.
- «цвет вкладок»: у каждой из 7 вкладок сетка `.pa-grid` на **7 колонок × 14 квадратов** (`.pa-sw`, `aspect-ratio:1`, ~1/7 ширины блока) — «огромные квадраты», всегда развёрнутая простыня, текст на кнопке-сбросе 9px.
- Контраст текста на акценте: грубое правило `lumOf(acc) > 0.45 ? тёмный : белый` — в «мёртвой полосе» яркости (~0.18–0.20) оба варианта дают < 4.5:1.

## Что сделано

1. **`web/src/lib/color.js` (новый, чистый модуль без DOM)** — сюда переехали `rgbOf/lumOf/mixHex` из `prefs.js` (prefs.js реэкспортирует `lumOf` — API не сломан), плюс:
   - `contrast(a,b)` — WCAG-отношение яркостей `(L1+0.05)/(L2+0.05)`;
   - `pickInk(bg)` — автоподбор текста: берём `#101114` или `#ffffff`, у кого контраст больше;
   - `fitAccentInk(bg, target=4.5)` — если в «мёртвой полосе» ни белый, ни тёмный не дотягивает до 4.5:1, подправляет сам фон (шаги по 2%, смешивание максимум 60%, в сторону выбранного текста), пока контраст не наберётся;
   - `ACCENT_PALETTE` — палитра (см. ниже).
2. **`web/src/components/ColorSwatches.jsx` (новый)** — `Swatch` (круглый, **26px**, кольцо `0 0 0 2px var(--sf), 0 0 0 4px var(--acc)` + галочка `Check`, тултип `data-tip` с названием цвета, `aria-pressed`) и `SwatchRow` (подпись раздела **слева** `96px`, свотчи справа в одну строку, `flex-wrap` — на 375px переносятся, вёрстка не ломается).

## Контраст и автоподбор — как реализовано

- Формула WCAG: `L = 0.2126R'+0.7152G'+0.0722B'` (лин. по sRGB), `ratio = (Lmax+0.05)/(Lmin+0.05)`, AA = **≥ 4.5:1**.
- `pickInk(bg)` → `contrast(bg,'#101114') >= contrast(bg,'#ffffff') ? '#101114' : '#ffffff'` (максимум из двух).
- Пробельная зона L≈0.1833–0.202 (белый < 4.5, тёмный < 4.5, например `#7a7a7a`) → `fitAccentInk` двигает фон на ≤60% к чёрному/белому до порога. На палитре подгонка не сработала ни разу — худший случай `#8a5cff` даёт 4.54:1 тёмным текстом.
- Семантические `--pos/--neg/--warn/--ai` `apply()` не трогает вообще — выбор акцента их перекрасить не может.
- Тест (7 кейсов): яркость, 21:1, порог #767676, палитра ≤10, **каждый из 10 цветов ≥ 4.5:1**, автоподбор белый/тёмный, «мёртвая полоса» `#7a7a7a` → фон подправлен до ≥ 4.5, достаточные цвета не меняются.

## Чек-лист ручной проверки для владельца

1. Настройки → «тема и цвет»: сверху один ряд «акцент приложения» — 10 круглых свотчей 26px в строку; наведение → тултип с названием цвета; клик → **весь интерфейс перекрашивается сразу**, без перезагрузки; выбранный имеет кольцо + галочку.
2. Перезагрузить страницу — выбор на месте (localStorage `ui.prefs.v1`; синий акцент также синкается на другое устройство через `/api/ui-prefs`).
3. Блок «цвет для каждого раздела» — **закрыт по умолчанию**; по клику разворачивается: подпись раздела слева, свотчи справа, первый — «как всё». Кнопка **«сбросить»** возвращает все разделы к цвету приложения.
4. **Семантика**: выбрать любой акцент (включая лайм/красный) → просроченные задачи/заказы остаются красными, ожидание — янтарным, деньги/ок — лаймовым, ИИ — фиолетовым (проверить на «Сегодня», задачах, финансах).
5. Контраст: в **обеих темах** текст на кнопках/активном пункте меню читается на любом из 10 акцентов (тёмный/светлый подбирается автоматически).
6. **Мобильный 375px** (Chrome DevTools, iPhone SE/X): Настройки → «вид» — нет горизонтального скролла, свотчи переносятся максимум в 2 строки, подписи слева не наезжают; тултипы не рвут вёрстку.
7. «сбросить вид» (внизу) — возвращает дефолтный синий и `pageAccents: {}`.
