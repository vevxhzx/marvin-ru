# Ревью D — СЦЕНАРИИ И ИНТЕРФЕЙС (e2e)

Ветка `overnight-crm`. Область: `tests/e2e/specs/*.spec.js` — новые Playwright-спеки
для непокрытых e2e-путей (финансы, экспорт, задачи, чат-правило, календарь, оплата
заказа, настройки «вид», память, доступность). Правки только в спеках и этом отчёте;
`web/src`, `core/**`, `web/site` не тронуты (сборка `npm run build` выполнялась,
`git status --porcelain web/site` пуст).

Запуск (отдельный порт, общая демо-БД стенда):

```powershell
cd web
$env:E2E_PORT='8921'; npm run test:e2e
```

## 4. Слабые места существующего покрытия

До этой ветки e2e-набор состоял из четырёх спек (`smoke`, `people`, `orders`,
`cash_chart` — 22 теста). Что оставалось за бортом:

1. **Чат и офлайн-правила.** Ни один тест не открывал `Ctrl+J` и не проверял, что
   команда «задача: …» реально создаёт запись и что отмена её убирает — самая
   хрупкая связка UI ↔ `core/brain/quick.py` ↔ `undo.py` была покрыта только
   pytest-юнитами. Сейчас поток отмены проверяется рабочей командой «отмена»,
   а доступность кнопки «отменить» в шапке чата — отдельным падающим тестом (D6).
2. **Деньги: ручные операции и периоды.** Создание/удаление траты, фильтры и
   переключатель периода на `/finance` не проверялись вовсе; баг вида
   «период „всё“ → days=0 → пустая история» жил бы незамеченным.
3. **Экспорт данных.** Ссылки `/api/export/*.csv` в настройках не кликались ни в
   одном тесте — регресс шапки/`Content-Disposition`/BOM не ловился бы.
4. **Оплата заказа.** `orders.spec.js` закрывал форму заказа, но не «Записать
   оплату»: идемпотентность двойного клика и возврат статуса `paid → done` при
   удалении дохода не проверялись (в `tests/` это только pytest).
5. **Память.** `/memory` не открывался: жизненный цикл факта и правка стиля
   (регресс 422 на `PUT /api/facts/style`) оставались без e2e.
6. **Настройки «вид».** Тема, аккордеон и свотчи цвета не проверялись, как и
   персистентность `data-theme` после reload.
7. **Доступность.** Фокус-ловушка шторок, Esc, дубли `id` и чтение консоли на
   десяти вкладках не сканировались вообще — существующий a11y-сканер
   `orders.spec.js` смотрит только на кнопки заказов.
8. **Мобильный проект.** Прогон шёл только с десктопным вьюпортом; ряд сценариев
   (Tabs/фокус на 375px, скачивание CSV в мобильном Chromium) не выполнялся.

Новые спеки закрывают пункты 1–7; осознанно не покрыты: звук/голос, Telegram-канал,
SSE-стрим `/api/events/stream` (только игнорируется в консольных ошибках) и
multi-tab поведение.
