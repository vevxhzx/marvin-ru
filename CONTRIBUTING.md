# Как помочь проекту

Спасибо, что хочешь поучаствовать. Ниже — коротко и по делу. Техническое устройство и запуск — в [docs/development.md](docs/development.md) и [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Нашёл баг или хочешь фичу

1. **Сначала загляни в issues** — возможно, уже есть.
2. **Баг** — заведи issue по шаблону `bug.yml`. Приложи: что делал, что ожидал, что получилось, лог из окна `start.bat` (или `docker compose logs assistant`) **без токенов и ключей**.
3. **Идея** — issue по шаблону `feature.yml`: опиши словами, как это должно работать, и пример фразы ассистенту, если речь о шаблонах.
4. **Уязвимость** — не публичным issue, а по правилам [SECURITY.md](SECURITY.md).
5. **Правка** — форкни, создай ветку, сделай изменение, пришли pull request по шаблону.

## Ветка и коммиты

- Ветка от `main`: `fix/короткое-описание` или `feat/короткое-описание`.
- Сообщения коммитов — [Conventional Commits](https://www.conventionalcommits.org/ru/v1.0.0/): `feat:`, `fix:`, `docs:`, `test:`, `refactor:`, `chore:`. Пример: `feat: новый шаблон «кто задерживает оплату»`.
- Один PR — одна цель. Не смешивай фичу, рефактор «ради красоты» и переезд файлов в одном PR.

## Стиль кода

- **Python** — 3.11+, PEP 8, четыре пробела, импорты по алфавиту. Ручки-комментарии — почему так, а не что делает строка.
- **Фронт** — React + Vite + Tailwind, без новых зависимостей без нужды. Стиль соседних файлов важнее личных предпочтений.
- Держись структуры проекта: бизнес-логика — в `core/services/`, работа с моделью — через `core/tools/registry.py`, настройки — через `core/config.py` (`EDITABLE`), не хардкодь пути и секреты.

## Тесты

Перед PR:

```bash
python -m pytest tests -q     # Python: ядро, API, сервисы (офлайн, временная БД)
npm test                      # Node-стенд: API-тесты на :3999
```

- Python-тесты не должны ходить в сеть и не должны зависеть от твоей реальной базы.
- Особенно приветствуются **новые фразы-шаблоны** в `core/brain/quick.py` и тесты к ним (см. `tests/`).
- Статический анализ (по желанию): `ruff check core` (входит в `requirements-dev.txt`).

## Что НЕ коммитить

Эти файлы в `.gitignore` — и должны там остаться:

- `.env`, `.env.*` (кроме `.env.example`) — секреты и ключи;
- `config.yaml` — токен бота, ключи облака, Google;
- `data/` целиком — база, медиа, бэкапы, модели, `api_token`, `session_secret`;
- `*.db`, `*.sqlite*` — личная база;
- `node_modules/`, `dist/`, `__pycache__/`, `.venv/` — артефакты.

**Ничего личного в репозиторий.** Ни реальных имён и сумм, ни скриншотов с данными, ни логов с токенами. Если в примере нужен человек — «Ваня», «Пятёрочка».
