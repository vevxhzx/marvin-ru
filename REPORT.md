## 1. Что объединено

**Основа — Jarvis** (`jarvis-main`): все данные, логика и личные фичи остались как были.

- база `data/jarvis.db` (**путь не менялся**), быстрые команды, команды-шаблоны, сценарии,

- сохранены оба варианта переменных окружения: новые `ASSISTANT_*` **и** старые `JARVIS_*`
  (`config.py`, `auth.py`, `run.py`) — из-за этого работают jarvis-тесты и `mac/host.py`.

**Из Marvin** взято:

- **ядро** (`core/`): оно в Marvin новее по функциям — каскад галочек событие↔задача↔заказ
  (`event.task_id` / `event.order_id`), `/api/finance/forecast`, более ранние исправления судьи,
  `.env` как источник настроек, `setup_done()`, `identity.py` (имя/бренд ассистента);
- **веб-интерфейс и дизайн** (`web/src`, `web/public`, собранная `web/site`) — новый UI целиком;
- корневые скрипты, docker, CI, документация, тесты.

**Правило выбора при расхождениях:** если файл в Marvin новее/богаче — берём Marvin и
дописываем личные фичи Jarvis; если у Jarvis версия полнее (README, CHANGELOG, ROADMAP,
LICENSE/NOTICE) — остаётся jarvis-версия. Все расхождения recorded в `FEATURES.md`.

## 2. Что переписано, починено и почему

1. **Мастер первого запуска нерабочий в исходнике Marvin.** В `marvin-ru-main/core/api/app.py`
   роутов `/api/setup/*` просто нет (есть только `setup.html` и `setup_done()`) — это баг
   апстрима, не следствие слияния. Решение: в `config.yaml` проставлено `setup: done: true`,
   чтобы мастер не блокировал первый запуск. Сам файл мастера сохранён — если захочешь его
   оживить, нужны роуты `/api/setup/start|step|finish`.
2. **Судья перехватывал точные правила** (`core/brain/agent.py`, `_disputed()`).
   Marvin-овский судья ставился впереди шаблонов и записывал
   «снял 3000 наличных» и «цель: подушка 300к к марту» как **доход**, а «пришёл аванс … за ролик» —
   как обычный доход вместо оплаты заказа. Теперь `_disputed()` возвращает `None`, если у фразы
   есть точный шаблон (снятие/перевод, цели/копилка, оплата заказа, `50/30/20`, «заказ: …»).
   Судья по-прежнему решает по-настоящему спорные фразы («сайт 15000», «отдал Ване 2000»).
3. **Восстановление бэкапа падало на Windows** (`core/services/scheduler.py`).
   `Path.replace` над открытым SQLite-файлом → `WinError 5`. Перед подменой пул соединений
   закрывается (`engine.dispose()`), новые соединения SQLAlchemy откроет сам.
4. **В настройках не хватало трёх роутов** (`core/api/app.py`): `/api/edition` (GET/POST),
   `/api/client/info`, `/api/llm` — они были только в Node-стенде `server.ts`, а сайт раздаёт
   Python-сервер, поэтому раздел «Настройки → Windows-клиент» показывал ошибку.
   Формы ответов сделаны один в один как в `server.ts`.
5. **Сборка фронта** (`vite.config.ts`, `web/postcss.config.js`, `web/tailwind.config.js`,
   `tsconfig.json`): после удаления дубля сборка из корня ломалась (tailwind искал конфиг от
   `cwd`). Пути сделаны абсолютными — `npm run build` в корне и в `web/` дают идентичный результат.
6. **`.gitignore` был написан до` node_modules`** — в коммит `ef17aaf` по ошибке попали 10 184
   файла `node_modules/`. Индекс починен (`git rm --cached`), сами файлы на диске остались.
7. **Облако отвечало мусором: «Тратил пока [сумма]»** (`core/brain/llm.py`). Анонимайзер
   (его код байт-в-байт совпадает с Marvin) подменяет суммы/имена на `[сумма]`, `[имя]` перед
   отправкой в облако, а модель отвечала этими же скобками. Добавлена подсказка в системный
   промпт: плейсхолдеры в ответ не тащить, про скрытое значение — молчать или сказать без цифры.
   Значения в облако по-прежнему не уходят — приватность не изменилась.
8. **Облако пересказывало старую историю как текущую** («задачи — тест-проверка объединения»,
   хотя задача была удалена часами раньше — в базе её нет, в истории чата есть).
   В промпт `via_gemini` добавлено правило: история — только для тона разговора, актуальное
   состояние брать из блока «что ты знаешь о хозяине», на «как дела» отвечать коротко без
   перечисления задач и сумм.

## 6. Известные ограничения

1. **Мастер setup без API** (см. §2.1) — сайт стартует сразу с готовой конфигурацией.
2. **`server.ts` (Node-стенд) — отдельная реализация API** с набором роутов, не совпадающим с
   Python (там есть `/api/llm`, `/api/edition`, `/api/client/info`, которых не было в Python —
   сейчас добавлены и туда). Запускать оба одновременно не нужно; тесты `npm test` используют
   свой порт 3999 и конфликтов не создают.
3. Переключатель «профиль: Джарвис / Марвин» в настройках теперь только **сохраняет выбор**
   (в Python-версии нет публичных zip-архивов Marvin, которые качал Node-стенд).
4. Сборка `web/site` зафиксирована в git, чтобы сайт работал без `npm install`; после правок в
   `web/src` пересобери: `build_web.bat`.
5. В логах предупреждение `Groq: модель «groq/compound» отвергнута (404)` — настроенный провайдер
   её больше не отдаёт, но есть автоматический фолбэк на `openai/gpt-oss-120b`, ответы приходят.
   Если захочешь убрать предупреждение — поменяй модель в настройках (⚙ → мозг).

## 7. Как запускать

```bat
install.bat   :: один раз: зависимости и config.yaml
start.bat     :: бот + сайт на http://localhost:8765
```

- без Telegram: `python run.py --no-tg`
- пересборка сайта: `build_web.bat` (или `cd web && npm run build`)
- Node-стенд: `npm run dev` → http://localhost:3000
- тесты: `python -m pytest tests -q` · `npm test`
- переменные окружения: см. `.env.example` (в git не попадают)

Подробная структура — в `README.md`, что умеет каждый проект — в `FEATURES.md`,
